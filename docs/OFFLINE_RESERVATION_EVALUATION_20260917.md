# 离线 CABLE：路径预留、分散选择与重新训练的实验

日期：2026-09-17。已完成 5,800 次主实验运行：72 次预检、2,304 次训练、720 次验证、2,704 次独立测试。正式测试包含 12,686,284 条流，全部完成。另有 8 次旧算法回归和 2 次新策略确定性复跑。没有在线参数更新。

## 1. 直接结果

**结论：All-to-All 的问题可以明显缓解，但本轮完整学习方案还不适合整体替换原 CABLE。** 预留记账是值得保留的组件；加入分散选择和本轮离线训练后，All-Reduce 与普通流量仍有退化。真实奖励训练也没有稳定超过奖励打乱训练，因此本轮不能证明这些收益主要来自 RL。

本轮新增了“按目的机架／路径记账的预留负载”和“近优路径按容量分散选择”，并做了离线重新训练。下列数字均为新学习模型相对所列对照的变化，负数表示更快。每个运行先计算自己的 P95/P99，再在同条件下比较；不把所有流混成一个分位数。

**All-to-All，在训练覆盖的规模与消息大小、全新测试种子上：** 相对原 CABLE，P95 -21.81%（95% 区间 -23.74% 至 -20.00%），P99 -26.43%（95% 区间 -29.99% 至 -23.28%）。

**All-to-All，在未见过的 48 主机、16/128 KiB 条件上：** 相对原 CABLE，P95 -47.23%（95% 区间 -50.69% 至 -43.00%），P99 -48.05%（95% 区间 -51.23% 至 -44.80%）。

**All-Reduce，熟悉规模、全新测试种子：** 相对原 CABLE，P95 +4.46%（95% 区间 +2.04% 至 +7.23%），P99 +9.38%（95% 区间 +6.43% 至 +11.85%）。

**All-Reduce，未见过的 48 主机、3 MiB 张量：** 相对原 CABLE，P95 +9.30%（95% 区间 +4.87% 至 +12.56%），P99 +6.15%（95% 区间 +1.64% 至 +11.11%）。

普通流量的回归结果，相对原 CABLE：

- Uniform：P95 +2.07%，P99 +3.29%。
- Storage：P95 +2.40%，P99 +2.57%。
- 快速变化的热点：P95 +1.87%，P99 +3.11%。
- 突发流量：P95 +1.55%，P99 +0.44%。

## 2. 学习本身贡献了多少

以下在熟悉规模的独立测试条件上，先在各流量类型内部等权，再对六类流量等权聚合。区间使用 10,000 次流量种子块／模型谱系重采样。四个测试种子、三个训练谱系的区间不覆盖所有可能网络或重新设计训练集的不确定性。

- 相对原 CABLE：P95 -2.05%（95% 区间 -2.96% 至 -1.06%），P99 -2.05%（95% 区间 -3.13% 至 -1.10%）。
- 相对**完全相同新机制、参数不训练的初始规则**：P95 -1.69%（95% 区间 -2.10% 至 -1.18%），P99 -1.67%（95% 区间 -2.16% 至 -1.03%）。
- 相对同预算的**奖励打乱训练**：P95 +0.46%（95% 区间 -0.06% 至 +1.06%），P99 +0.61%（95% 区间 -0.16% 至 +1.37%）。
- 相对**只做预留、不做分散选择的固定规则**：P95 +1.83%（95% 区间 +1.13% 至 +2.54%），P99 +2.56%（95% 区间 +2.04% 至 +3.04%）。

这些对照必须一起阅读。原 CABLE 对比衡量完整方案变化；相同机制的固定参数对照衡量重新训练的增量；打乱奖励对照检查收益是否依赖正确的策略—奖励对应关系。不能把新机制相对原 CABLE 的全部收益算成 RL 收益。

**目前更值得继续研究的是只做预留的固定规则。** 在熟悉规模、独立测试种子上，它相对原 CABLE 的六类等权 P95/P99 分别下降 **3.81% / 4.50%**；All-to-All 下降 **22.22% / 27.14%**，All-Reduce 下降 **3.79% / 2.42%**。完整学习版反而比它慢 1.83% / 2.56%。这个消融说明，本轮固定的近优路径分散窗口存在代价，不能把“增加机制”当成必然改进。

预留单独方案也不是全面胜出：Uniform、Storage、快速热点和突发流量的 P99 分别变化 +3.06%、+0.40%、+1.82%、+1.28%；其中 Storage 与突发流量的区间跨过零。它使用新的固定评分初值，因此它相对旧学习模型的全部收益也不能单独归因于预留变量。完整统计还提供了各组件相对原同信息固定规则的比较。

这次实验支持保留预留机制、重新考虑分散选择，并继续解决普通流量的退化；它尚不足以支持“重新训练已经学会适应所有流量”的结论。原模型继续保留，新实现默认关闭。

## 3. 具体实现

**预留是短期分配记账，不是精确的剩余字节数。** 每个源 leaf 为输出端口，以及“输出端口＋目的前缀”维护独立计数。每给新跨机架流分配一次路径，就加 1；计数按 1 ms 时间常数指数衰减。它不读取流的最终大小，也不依赖仿真器的流完成通知。

目的前缀只来自已经收到的真实路由反馈；尚未收到时按包中的目的 IP /32 分组。所有候选状态和选择概率确定之后，才更新被选路径的计数，避免把本次决定提前放入观测。

端口计数乘本地 1,000 字节的链路发送时间，成为 `x22`；目的／路径计数乘收到的远端链路发送时间，成为 `x23`。这两个位置仅在新功能启用时替换原有未使用的评分输入。完整观测、前缀、物理端口、概率、随机数和选择都保存在 `.offline.csv`。

**分散选择**从分数不超过最小值加 0.016 ms 的候选中，按本地链路容量分配概率。随机数由可见 flow key、源 leaf 和固定部署种子确定。它没有逐包随机路由：新流只选一次路径，后续整流保持路径。

**评分器**固定本地时延系数为 1，训练八个系数：远端时延、本地／远端链路发送时间、远端变化量、目的侧／端口历史流量、端口／目的侧预留量。队列、历史和预留惩罚设非负边界；显式发送时间和变化量系数允许有符号。完整范围写入实验协议。

模型从显式固定规则及预留权重初始化，并非从零策略或原 CABLE 模型继续训练。执行格式沿用旧 `ROUTE_DQN_V1` 容器，实际仍是线性评分的 ARS 策略搜索，没有 DQN、TD loss 或在线反向传播。

新功能默认关闭。代码入口为 `OFFLINE_PATH_ENABLE`，预留和分散分别由 `OFFLINE_PATH_RESERVATIONS`、`OFFLINE_PATH_SPREAD` 控制。原模型文件没有被替换。

## 4. 初始分配是否真的变好了

固定展示样本使用首个测试种子 98601、模型谱系 0、64 主机、每对端 64 KiB。目的侧负载按链路容量应承担的理想字节数归一化。

- 对称拓扑：原 CABLE 的最重路径为理想值的 2.04 倍，学习版为 1.29 倍；P99 从 86.40 ms 降到 55.50 ms。同机制固定参数对照的峰值为 1.18 倍、P99 为 51.16 ms。
- 非对称拓扑：原 CABLE 的最重路径为理想值的 1.81 倍，学习版为 1.34 倍；P99 从 75.83 ms 降到 59.03 ms。同机制固定参数对照的峰值为 1.23 倍、P99 为 53.32 ms。

这个样本支持预留／分散机制确实改变了路径分配，同时也提醒：改善分配不等于学习版必然胜过固定参数。它是展示样本，不替代全部种子和条件的统计。

## 5. 离线训练与数据隔离

训练使用 8 轮 ARS，每轮 4 个正负成对方向、选择 2 个方向更新，3 个优化谱系。真实奖励组与打乱奖励组从相同参数出发，使用相同方向种子、仿真预算、验证规则；打乱组只改变 measured return 与扰动方向的对应关系。

每个扰动在六类流量上运行。八轮覆盖两种拓扑，以及 32/64 主机、8/64 KiB All-to-All 的全部组合。每轮使用新的训练流量种子。

普通流量的优化目标：

```text
loss = 0.20 log(mean FCT) + 0.40 log(P95 FCT) + 0.40 log(P99 FCT)
```

集合通信的目标：

```text
loss = 0.15 log(mean FCT) + 0.25 log(P95 FCT)
     + 0.25 log(P99 FCT) + 0.35 log(整个任务完成时间)
reward = -loss
```

时间用 ms，取自然对数，各类型等权。真实流完成结果仅在整个仿真结束后供离线优化器使用，不进入部署时的 actor 输入。

- 训练流量种子：98401–98408。
- 验证流量种子：98501、98502；比较第 0/4/8 轮，每组统一选一个轮次。
- 测试流量种子：98601–98604，所有测试流量均在模型选择冻结之后生成。
- 优化种子与部署时 flow hash 种子另外固定，不与流量种子混为一个变量。

8 轮只是本轮预定的搜索预算，没有宣称已找到最优策略或充分收敛。未单独消融奖励函数、训练流量组成、参数边界及初始化，因此不能分别量化这些设计的贡献。

## 6. 正式评测范围

128 主机、8 leaf、8 spine。主机链路为 1 Gbps；对称网络的八条上联各 750 Mbps，非对称网络为四条 1 Gbps 加四条 500 Mbps；每 leaf 总容量均为 6 Gbps。沿用 DCQCN、IRN、PFC 关闭、50 MiB 缓冲和先前 ECN／ConWeave 参数，没有测试后为基线调参。

正式算法包括 ECMP、weighted ECMP、CONGA、适配 ConWeave、原同信息固定规则、原 CABLE、之前的三项删除方案，以及新机制的固定、预留单独、分散单独、真实训练、奖励打乱训练对照。学习相关组保留三个模型／部署种子。固定组件消融没有各自重新训练专属模型。

普通流量包括 Uniform、Storage、快速热点变化和突发流量，每次注入 50 ms、负载 0.35。集合通信为真实依赖驱动的单次 direct All-to-All 或 ring All-Reduce，没有 GPU 计算或 NCCL 软件开销。

熟悉条件包括 32/64 主机 All-to-All 的 8/64 KiB 每对端，以及 32/64 主机 All-Reduce 的 1 MiB 张量。未见条件为 48 主机 All-to-All 的 16/128 KiB，以及 48 主机 All-Reduce 的 3 MiB。48 主机属于参与规模插值，128 KiB All-to-All 和 3 MiB All-Reduce 超过本轮对应训练消息大小，不能据此推广为任意流量泛化。

最初协议把未见 All-Reduce 张量写为 4 MiB；静态检查发现它不能被 48 整除，等块 ring 生成器不接受。在验证选模和生成任何测试流量之前，将这一个值修正为 3 MiB，保持训练、验证、种子和运行数不变。原协议完整保留，修正单独记录并哈希。

P95/P99 包括每次运行的全部流，包括机架内流。集合通信的流 FCT 不含启动前的依赖等待，整个任务完成时间则包含所有依赖。下图保留全部算法、规模、消息大小和两个拓扑。

## 7. 核验与限制

旧算法在两个拓扑上的 8 次回归产生与旧版本逐字节相同的 FCT／诊断输出。新固定机制和新学习模型的两次复跑，FCT、候选状态、完整选路日志也逐字节相同。

24 次预检和 12 次带训练后系数的运行独立核验了预留状态、线性评分、哈希随机数、候选概率和最终动作。另对首个测试种子、首个谱系、所有六类流量和两个拓扑的五个新机制组进行 60 次完整重建，覆盖 307,660 次初始选路。展示样本按固定规则选择，不按性能挑选。

720 次验证的原始 FCT 与选模目标已独立重算。正式测试进一步检查所有原始 P95/P99、模型／配置哈希、共同流量、模型选择先于测试生成，以及在线训练始终关闭。725 项比较的点估计和 10,000 次重采样置信区间，另用按抽样频数加权的实现独立重算，最大差异小于 0.000000000001 个百分点。详细结果见核验文件。

预留计数只估计短期分配压力，不能精确区分长短流的剩余工作；过期前的已完成流也会留下衰减计数。近优窗口和衰减时间固定，未做完整参数扫描。新机制沿用真实反馈报文，不新增控制报文，但没有建模硬件执行浮点评分／计数的时间与资源开销。
